# Lisperpaw — 日本語サイトとして勝ちやすい差別化ポイント

**作成日**: 2026年4月30日  
**位置づけ**: 1ページ要約  
**目的**: 競合比較を踏まえて、Lisperpaw がどこで勝つべきかを短く固定する

---

## 1. 結論

Lisperpaw が勝ちやすい場所は、「日本語で、ブラウザですぐ試せて、問題演習まで一体化している Common Lisp 学習体験」である。

英語圏には強い無料教材や演習サイトがある。一方で、日本語で、初学者が迷わず入り、実際に手を動かし、継続しやすい形にまとまったサイトはまだ薄い。

したがって、正面から英語圏の総量と戦うのではなく、次の 3 点で勝つべきである。

1. 日本語で迷わず学び始められること
2. その場で試して理解を確認できること
3. 続けやすい学習導線があること

---

## 2. 競合に対して勝ちやすい軸

### 軸1: 日本語の学習体験

- 英語の壁なしで始められる
- 初学者向け説明を日本語の感覚で整理できる
- 「なぜそう書くのか」を日本語で説明できる

Exercism や Cookbook は強いが、主戦場は英語である。ここは明確な差別化余地がある。

### 軸2: 学ぶ、試す、解くの一体化

- ガイドだけで終わらない
- REPL だけでも終わらない
- 問題演習だけでも終わらない

Lisperpaw は、ガイド、エディタ、REPL、問題を一つに束ねられる。これは単体の書籍や単体のリファレンスより強い。

### 軸3: 初学者向けの導線設計

- 何から始めるかが分かる
- 次に何をやるかが分かる
- 復習すべき項目が分かる

競合には情報量が多いものが多いが、初学者にとっては導線が重いことも多い。ここは設計で勝てる。

### 軸4: Common Lisp の入口特化

- Scheme や Clojure まで広げすぎない
- まずは Common Lisp 初学者の成功体験に集中する
- 仕様差分は隠さず、学習用であることを明示する

総合 Lisp ポータルよりも、「Common Lisp 学習の入口」として尖らせた方が勝ちやすい。

---

## 3. 勝ちに行くべきでない軸

### 英語圏の総量勝負

- 問題数だけで Exercism に正面対抗する
- 網羅性だけで Cookbook や Practical Common Lisp に勝とうとする
- 仕様の完全性だけで HyperSpec に近づこうとする

この方向は開発量に対して差別化効率が悪い。

### 早すぎる課金壁

- 基本構文の学習だけを有料化する
- 入門部分で閲覧制限を強くする
- 無料価値が弱い状態でサブスクを置く

Common Lisp の主要教材は無料が強い。課金は深さと継続価値で作る必要がある。

---

## 4. 当面の差別化メッセージ

外向けには、次のような一文に寄せるのがよい。

> 日本語で Common Lisp を学び、すぐ試し、問題で定着できる学習サイト。

もう少しプロダクト寄りに言うなら、次でもよい。

> Lisperpaw は、日本語で Common Lisp を学ぶための、ガイド、実行環境、演習を一体化した学習プラットフォームである。

---

## 5. 優先して伸ばすべき要素

1. 問題数の増強
2. 初級から中級入口までの学習パス
3. 復習導線と進捗可視化
4. 中級トピックの拡充
5. 仕様差分の明示

特に重要なのは、「量」だけではなく「次に何をやれば良いかが分かること」である。

---

## 6. 将来の有料化と相性が良い差別化

無料で信頼を作り、有料で深さを売る構成が最も自然である。

有料化と相性が良いのは次の領域である。

- 中級から上級の体系化コース
- 実践課題や小規模プロジェクト
- エラー辞典とデバッグ解説
- 復習キューと進捗同期
- 定期的な新規問題追加

逆に、単に REPL を使えるだけ、基本文法を読めるだけ、という価値は有料化しにくい。

---

## 7. 意思決定の基準

今後の機能追加は、次の問いで判断する。

1. 日本語初学者の理解を前進させるか
2. 学ぶ、試す、解くの一体感を強めるか
3. 継続利用の理由を増やすか
4. 無料で代替しにくい価値に近づくか

この 4 つに効かない変更は、優先度を下げてよい。
