## 1. この文書の結論

日本市場を前提にした場合、問題数の目標は次の 3 段階で考えるのが妥当である。

1. **最低ライン: 120 問**
   - 日本語初学者が入門から中級入口までをサイト内で一通り学べる水準
2. **推奨ライン: 144 問**
   - 「このサイトだけでかなり進める」と感じてもらえる現実的な主目標
3. **拡張ライン: 180 問**
   - 実務寄りミニ課題と読解・デバッグまで含めた競争力のある水準

**200 問ライン** は、近い将来の必須目標ではない。これは、マクロ、package、CLOS、condition system、file I/O など、現行学習モードの外にある要素を扱う条件付き拡張ラインとして位置づける。

本プロジェクトの当面の推奨目標は **144 問** とする。

## 2. 日本市場を前提にした設計方針

問題数を増やすときは、単純な総数ではなく、日本語学習者が継続しやすい構成を優先する。

### 重視すること

- 日本語で迷わず始められること
- 1 問 1 学びが明確であること
- 学んだ内容をすぐエディタと REPL で試せること
- 演習が抽象的すぎず、日本の学習者にとって用途が想像しやすいこと
- 入門問題だけで終わらず、中級入口までつながること

### 日本市場向けに相性が良い題材

- 料金計算、消費税、割引、送料、手数料
- シフト、当番、予約、受付順、営業日判定
- 在庫、商品コード、売上集計、ランキング
- 文字列整形、帳票前処理、コード変換、分類
- 条件ルール、判定ロジック、簡易な知識処理

### 当面は広げすぎないもの

- package system
- CLOS
- condition system
- stream / file I/O
- マクロ中心の高度なメタプログラミング

これらは 200 問ラインの条件付き拡張、または将来の実処理系モードで扱う。

## 4. 目標ライン別の位置づけ

### 120 問ライン

- 目的: 入門から中級入口までをサイト内で完結させる
- 想定ユーザー: 日本語で Common Lisp を学びたい初学者から初中級者
- 必須要素:
  - 基本構文の穴を埋める
  - リスト、再帰、高階関数、スコープを厚くする
  - 文字列、数値、条件分岐の現実寄り問題を追加する
  - 日本向けミニ業務課題を少数でも入れる

### 144 問ライン

- 目的: 推奨ライン。サイト単体の満足度を一段上げる
- 想定ユーザー: 「このサイトだけでもかなり学べる」と感じてほしい層
- 必須要素:
  - 木構造、連想リスト、シンボルとクォートを整理する
  - 読解、デバッグ、修正型問題を入れる
  - 小さな実践ミニプロジェクトを開始する

### 180 問ライン

- 目的: 競争力のある学習密度にする
- 想定ユーザー: 中級手前から実務的な問題設定まで触れたい層
- 必須要素:
  - 業務ミニ課題を増やす
  - 総合問題を増やす
  - ミニプロジェクトを複数本用意する
  - 読解とデバッグを強化する

### 200 問ライン

- 目的: 将来の上限拡張
- 条件:
  - 現行学習モードで追加実装を進める
  - もしくはバックエンド側の実処理系モードを導入する
- 内容:
  - マクロ入門
  - packages と symbols の整理
  - CLOS 入門
  - condition system 入門
  - file / stream を使う問題

## 7. 日本市場向けに追加すべき問題テーマ

日本語学習者向けの差別化として、次のテーマを優先する。

### 料金・会計系

- 消費税計算
- 送料ルール
- 割引条件
- 手数料計算
- 売上合計と平均客単価

### シフト・運用系

- 当番表の割当
- 営業日判定
- 予約時間帯の重複チェック
- 受付順の整理
- 簡易スケジューリング

### 在庫・販売系

- 商品コードの分類
- 在庫引当
- 発注点判定
- ランキング上位抽出
- 売上データ集計

### 文字列・帳票前処理系

- 電話番号や郵便番号の整形
- 半角全角を除く基本的な前処理題材
- 文字列コードの分解と再構成
- ラベル整形
- フォーマット文字列の組み立て

### ルール判定・知識処理系

- 条件ルールによる顧客区分
- スコア判定
- 商品タグ付け
- 問い合わせ分類
- 簡易なルールエンジン風問題

これらは、日本での Lisp の商用利用文脈とも相性が良く、差別化と継続利用の両方に効く。

## 9. 120 問までの完了条件

120 問ラインに到達したと判断する条件は次の通りとする。

1. 入門から中級入口までの主要概念がカテゴリとして揃っている
2. 日本語学習者向けのミニ業務課題が 6 問以上ある
3. 読解・デバッグ問題が 6 問以上ある
4. 総合問題が 8 問以上ある
5. 問題一覧上で難易度とカテゴリの偏りが大きすぎない
6. 問題の説明、ヒント、解答が日本語品質として揃っている

## 10. 実行順の提案

問題追加は、次の順番で進める。

1. Wave 1 の 22 問
2. 最初の 24 問のうち、biz と debug を除く基礎 20 問
3. 読解・デバッグカテゴリのテンプレート整備
4. 日本向け業務ミニ課題のテンプレート整備
5. Wave 2 以降の追加

つまり、最初にやるべきことは「難しい総合問題を増やす」ことではなく、「日本語初学者が途中で落ちない基礎問題群を厚くする」ことである。

## 11. 補足

このロードマップは、**現行の学習モードを主軸にしたコンテンツ拡張計画** である。

そのため、200 問ラインを無理に急ぐよりも、120 問から 144 問の質を高く作る方が優先度は高い。実務的には、次の順が妥当である。

1. まず 120 問ラインを完成させる
2. 次に 144 問ラインで「かなり学べる」状態にする
3. その後に 180 問ラインを検討する
4. 200 問ラインは、対応機能や実処理系モードの条件が整ってから着手する
